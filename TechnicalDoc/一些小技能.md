## Ubuntu静态IP设置

> 具有图形化界面的Ubuntu的静态IP设置比较简单，在此不再阐述

* 识别网络接口

  ~~~bash
  $ ip addr
  1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
      link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
      inet 127.0.0.1/8 scope host lo
         valid_lft forever preferred_lft forever
      inet6 ::1/128 scope host noprefixroute
         valid_lft forever preferred_lft forever
  2: ens18: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
      link/ether bc:24:11:3a:8f:5b brd ff:ff:ff:ff:ff:ff
      altname enp0s18
      inet 192.168.3.226/24 brd 192.168.3.255 scope global ens18
         valid_lft forever preferred_lft forever
      inet6 fe80::be24:11ff:fe3a:8f5b/64 scope link
         valid_lft forever preferred_lft forever
  .......
  ~~~

  我们要配置的是`ens18`接口

* 编辑NetPlan配置文件

  可以在`/etc/netplan`中找到类似`01-netcfg.yaml`、`50-cloud-init.yaml`之类的配置文件

  ~~~bash
  $ vim /etc/netplan/50-cloud-init.yaml
  ------------------
  network:
    version: 2
    ethernets:
      ens18:
        dhcp4: no
        addresses:
          - 192.168.3.226/24
        routes:
          - to: 0.0.0.0/0
            via: 192.168.3.1
        nameservers:
          addresses: [8.8.8.8, 8.8.4.4]
  ~~~

  只要将`dhcp4`选项设置为`no`即可，然后手动配置这个接口的静态IP、路由默认网关等等

* 应用配置文件

  ~~~bash
  $ netplan apply
  ~~~

# Git-Related

* 创建新分支

  ~~~sh
  git branch newBranch
  ~~~

* 切换分支

  ~~~sh
  git checkout branchName
  ~~~

* 创建分支的同时切换到该分支

  ~~~sh
  git checkout -b newBranchName
  ~~~

* 从远程仓库pull指定分支到本地指定分支

  ~~~sh
  git pull origin remoteBranch:localBranch
  ~~~

  如果不屑本地分支名称，默认和远程分支同名

  ~~~sh
  git pull origin remoteBranch
  ~~~

* 将新分支推送到远程仓库

  ~~~sh
  git push origin branchName
  ~~~

* 本地创建的分支在远程仓库还没有这个分支的情况下推送

  ~~~sh
  git push --set-upstream origin branchName
  ~~~

* 删除本地分支

  ~~~sh
  git branch -d branchName
  ~~~

  如果报错`error:The branch "" is not fully merged`,使用-D强制删除

* 删除远程分支

  ~~~sh
  git push origin :branchName
  ~~~




# Trae-Related

* 使用Trae配置Debug

  https://ykzm.cn/zh/api/debugging.html#%E8%B0%83%E8%AF%95%E9%85%8D%E7%BD%AE

  示例配置

  ~~~json
  {
      "version": "0.2.0",
      "configurations": [
          {
              "name": "Launch Program",
              "type": "node",
              "request": "launch",
              "program": "${workspaceFolder}/app.js",
              "stopOnEntry": false,
              "args": [],
              "cwd": "${workspaceFolder}",
              "env": {
                  "NODE_ENV": "development"
              },
              "console": "integratedTerminal",
              "sourceMaps": true
          }
      ]
  }
  ~~~

  - **name**：配置显示名称
  - **type**：调试器类型（node、python、java 等）
  - **request**：请求类型（launch 或 attach）
  - **program**：要调试的程序入口
  - **args**：命令行参数
  - **cwd**：工作目录
  - **env**：环境变量
  - **stopOnEntry**：是否在入口处停止

  kind: Namespace

    name: k8s-learn
  
  ---
  # ================= Deployment =================
  apiVersion: apps/v1
  kind: Deployment
  metadata:
    name: nginx-deployment
    namespace: k8s-learn
    labels:
      app: nginx
  spec:
    replicas: 2
    selector:
      matchLabels:
        app: nginx
    template:
      metadata:
        labels:
          app: nginx
      spec:
        affinity:
          nodeAffinity:
            requiredDuringSchedulingIgnoredDuringExecution:
              nodeSelectorTerms:
                - matchExpressions:
                    - key: node-role
        tolerations:
          - key: node-role.kubernetes.io/control-plane
            operator: Exists
            effect: NoSchedule
          - key: node-role.kubernetes.io/master
            operator: Exists
            effect: NoSchedule
        containers:
        - name: nginx
          image: nginx:latest
          ports:
          - containerPort: 80
  
  ---
  # ================= Service =================
  apiVersion: v1
  kind: Service
  metadata:
    name: nginx-service
    namespace: k8s-learn
    labels:
      app: nginx
  spec:
    type: NodePort
    selector:
      app: nginx
    ports:
      - protocol: TCP
        port: 80
        targetPort: 80
  ~~~

* Release升级与回滚与卸载

  当Chart发布了新版本，或者想更新同一个版本的Chart包的同一个实例时可以使用helm升级与回滚

  ~~~sh
  helm upgrade [RELEASE] [CHART] [flags]		#更新一个Chart实例。
  helm history RELEASE_NAME [flags]			#打印一个Release的所有历史修订版本（Revisions）。
  helm rollback <RELEASE> [REVISION] [flags]	#回滚一个Release到指定版本。
  ~~~

  1. 升级

     将上述例子中的2个replicas换为3个，先修改values-replicas.yaml

     ~~~yaml
     prometheus:
     	prometheusSpec:
     		replicas: 3
     ~~~

     ~~~sh
     helm upgrade kube-prometheus-stack-1643553862 ./kube-prometheus-stack -n monitoring -f values-replicas.yaml
     ~~~

  2. 回滚

     通过`helm history`看部署的chart版本，我们将其回滚到revision 1

     ~~~sh
     helm rollback kube-prometheus-stack-1643553862 1 -n monitoring
     ~~~

     有一个很有意思的是，被卸载的release，可以通过回滚复活

* helm命令常用参数

  Helm的install/upgrade/rollback等子命令都有几个很有用的参数

  1. --timeout：等待Kubernetes命令执行完成的超时时间，默认是50毫秒，这里的值是一个Golang 的Duration。
  2. --wait：等待所有的Pod变成准备（ready）状态，PVC完成绑定，deployments至少有（Desired Pods减去maxUnavailable Pods）数量处于准备状态，Service都有IP成功绑定。如果到了--timeout指
     定的超时时间，那么这个Release就会被标记为FAILED状态。
