# 实习项目概述：SRE-Benchmark —— SRE 场景下的 Agent 效能评测平台

## 一、项目背景

- **项目定位**：构建面向 SRE（Site Reliability Engineering）场景的 Agent 效能评测平台，即 **SRE-Benchmark**。
- **问题来源一：模型选型难**
  - SRE-Agent 在实际应用中存在模型选型问题。
  - 选型需要综合考量成本、性能表现、数据隐私等多方面因素，难以简单决定。
- **问题来源二：框架迭代质量无法验证**
  - SRE-Agent 所依赖的 Harness 框架迭代速度较快。
  - 但缺少客观手段评价「迭代后的 SRE-Agent 是否表现更优」。
  - 因此需要一个统一平台，用来判定 Harness 框架的迭代质量。

## 二、遇到的问题

- **问题一：如何正确评价 SRE-Agent 的 SRE 任务完成质量**
  - SRE 任务结果较为开放、没有唯一标准答案。
  - 难以客观、量化的判断 Agent 是否真正、正确地解决了问题。
- **问题二：如何在动态环境下保证不同模型评测的公平性**
  - 实际运行环境是动态、多变的，不同模型的评测条件难以对齐。
  - 条件不一致会导致评测结果失真，模型之间无法公平比较。

## 三、解决方案

- **方案一：双链评估方法（评价完成质量）**
  - 同时从「结论正确性」与「执行路径合理性」两条链路进行评估。
  - 结论链：判断 Agent 给出的最终结论是否正确、是否真正解决了问题。
  - 执行链：判断 Agent 的执行路径是否合理、规范、符合预期。
  - 两者结合，综合衡量 Agent 针对 SRE 任务的完成质量。
- **方案二：统一基准保障公平（多模型评测）**
  - 所有被测模型使用同一套 Harness 框架运行。
  - 所有 case 使用统一的参考答案作为评价基准。
  - 从而保证不同模型在相同基准、相同条件下被评测，从机制上保障跨模型对比的公平性。

## 四、平台价值 / 意义

- 客观评价 SRE-Agent 在不同模型上的 SRE 任务完成质量。
- 为模型选型提供数据支撑（成本 / 性能 / 隐私之外的「效果」维度）。
- 为 Harness 框架的每次迭代提供可量化的回归判断依据，判定迭代是否更优。
