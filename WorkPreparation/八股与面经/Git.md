# 关于Git的Rebase、Verge？

简单来说：**Merge 是把两条线拧成一股，Rebase 是把其中一条线剪下来，接到另一条线的末尾。**

------

## 一、 Git Merge：保留真实的历史

`Merge` 是最常用的合并方式。当你执行 `git merge feature` 时，Git 会找到两个分支的共同祖先，然后将两边的改动合并在一起，生成一个新的 **Merge Commit**。

- **特点：** 非破坏性操作。它不会修改现有的任何提交，而是新增一个提交作为连接点。
- **优点：** 完整保留了分支的演进历史，你能清晰看到什么时候开了分支，什么时候合并回来的。
- **缺点：** 如果分支很多，提交历史会变得非常乱，充斥着各种 "Merge branch 'xxx' of ..." 的信息。

------

## 二、 Git Rebase：创造线性的历史

`Rebase` 的逻辑完全不同。当你执行 `git rebase main` 时，Git 会把你当前分支（feature）上所有独有的提交先“撤销”并临时存放，然后把你的分支起点挪到 `main` 分支的最新位置，最后把刚才存放的提交按顺序一个一个重新“贴”上去。

- **特点：** 历史重写。你会发现原来的提交 ID（SHA）变了，因为它们变成了全新的提交。
- **优点：** 历史极其干净。看起来就像是你直接在最新的 `main` 上开发一样，没有任何分叉。
- **缺点：** 篡改了历史。如果处理不当，可能会导致协作时的巨大混乱（见下文“金科玉律”）。
