### 前三个组件的配置

* 将grafana配置为NodePort访问

  ~~~sh
  cd /kube-prometheus-0.13.0/manifests
  vim grafana-service.yaml
  ~~~

  添加service类型为NodePort

  ~~~yaml
  apiVersion: v1
  kind: Service
  metadata:
    labels:
      app.kubernetes.io/component: grafana
      app.kubernetes.io/name: grafana
      app.kubernetes.io/part-of: kube-prometheus
      app.kubernetes.io/version: 9.5.3
    name: grafana
    namespace: monitoring
  spec:
    type: NodePort	# 修改部分
    ports:
    - name: http
      port: 3000
      targetPort: http
    selector:
      app.kubernetes.io/component: grafana
      app.kubernetes.io/name: grafana
      app.kubernetes.io/part-of: kube-prometheus
  ~~~

* 将grafana配置为可以匿名访问+允许面板嵌入，方便后面将监控面板放在前端界面中

  ~~~sh 
  vim grafana-config.yaml
  ~~~

  修改内容如下

  ~~~yaml
  apiVersion: v1
  kind: Secret
  metadata:
    labels:
      app.kubernetes.io/component: grafana
      app.kubernetes.io/name: grafana
      app.kubernetes.io/part-of: kube-prometheus
      app.kubernetes.io/version: 9.5.3
    name: grafana-config
    namespace: monitoring
  stringData:
    grafana.ini: |
      [date_formats]
      default_timezone = UTC
      [security]
      # 开启允许面板嵌入
      allow_embedding = true
      [auth.anonymous]
      # 开启免登录
      enabled = true
      # 组织名称（必须与Grafana里的实际组织名一致，默认是 Main Org.）
      org_name = Main Org.
      # 角色：Viewer(只读), Editor(编辑)
      org_role = Viewer
  type: Opaque
  ~~~

### 在Grafana中添加监控面板

* 首先访问grafana dashboard，根据自己的grafana地址不同而不同，此处略过如何在grafana中添加监控面板，具体过程上网查询，主要分为如下步骤

  1. 确定数据源，此处一般为Prometheus
  2. Grafana Home -> Dashboards -> New -> New Dashboard -> Add visualization -> Data Source选择Prometheus -> Queries选择Code -> 添加对应监控指标的promQL

* 接下来提供不同监控指标的promQL

  * NodeCpuUseRate

    ~~~promQL
    100 - (avg by (instance) (irate(node_cpu_seconds_total{mode="idle"}[1m]) * 100))
    ~~~

  * NodeMemUseRate

    ~~~promQL
    ( (node_memory_MemTotal_bytes - node_memory_MemFree_bytes - node_memory_Buffers_bytes - node_memory_Cached_bytes)
      /
      node_memory_MemTotal_bytes
    ) * 100
    ~~~

  * NodeNetworkRecieveRate

    **注意，不同设备的device部分可能不同，根据实际情况确定**

    ~~~promQL
    rate(node_network_receive_bytes_total{device="ens18"}[1m])
    ~~~

  * NodeNetworkTransmitRate

    **注意，不同设备的device部分可能不同，根据实际情况确定**

    ~~~promQL
    rate(node_network_transmit_bytes_total{device="ens18"}[1m])
    ~~~

  * NodeDiskUseRate

    **注意，不同设备的device部分可能不同，根据实际情况确定**

    ~~~promQL
    (1 - (node_filesystem_free_bytes{fstype!="",device="/dev/mapper/ubuntu--vg-ubuntu--lv"} / node_filesystem_size_bytes{fstype!="",device="/dev/mapper/ubuntu--vg-ubuntu--lv"})) * 100
    ~~~

  * TrainTicketCpuUseRate

    ~~~promQL
    (
      sum(rate(container_cpu_usage_seconds_total{namespace=~"tt|openebs",container!=""}[1m]))
    )
    /
    (
      sum(instance:node_num_cpu:sum)
    )
    * 100
    ~~~

  * TrainTicketMemUseRate

    ~~~promQL
    sum(container_memory_usage_bytes{namespace=~"tt|openebs",container!=""}) / sum(node_memory_MemTotal_bytes) * 100
    ~~~

  * TrainTicketServiceResponseTime

    **根据实际配置的blackbox-exporter服务地址确定**

    ~~~promQL
    sum(probe_http_duration_seconds{instance!="http://192.168.3.226:32241"}) by (instance)
    ~~~

  * TrainTicketServiceAccess

    **根据实际配置的blackbox-exporter服务地址确定**

    ~~~promQL
    probe_http_status_code{instance!="http://192.168.3.226:32241"}
    ~~~

  * ebpf-enable

    ~~~promQL
    sum by (instance) (ebpf_exporter_enabled_configs)
    ~~~

  * biolatency-read

    ~~~promQL
    sum by (le) (
      rate(ebpf_exporter_bio_latency_seconds_bucket{operation="read"}[2m])
    )
    ~~~

  * biolatency-flush

    ~~~promQL
    sum by (le) (
      rate(ebpf_exporter_bio_latency_seconds_bucket{operation="write"}[2m])
    )
    ~~~

  * panel-tile

    ~~~promQL
    histogram_quantile(0.90, sum by (le, device, operation) (rate(ebpf_exporter_bio_latency_seconds_bucket[5m])))
    ~~~

### 代码修改

其实并没有需要修改的代码，只需要将被移植到的Kubernetes集群的配置文件（默认为~/.kube/config)放在项目的`os-backend-app/K8sFunction/`文件夹下即可

### 镜像构建与服务部署

1. 在支持该后端项目运行的本地机器中执行如下命令构建镜像

   ~~~sh
   docker build -t os-backend-app:v1.0 .
   ~~~

   镜像构建完成后，在本地进行镜像导出

   ~~~sh
   docker save -o os-backend-app.tar.gz os-backend-app:v1.0
   ~~~

   将`os-backend-app.tar.gz`镜像文件发送到集群各个节点上

2. 集群节点镜像导入

   在集群各个节点上执行如下命令(以集群版本Kubernetes 1.28.15版本为例，使用containerd和nerdctl)

   ~~~sh
   nerdctl -n k8s.io load -i os-backend-app.tar.gz
   ~~~

   该命令将构建的镜像导入各个节点的k8s.i命名空间镜像仓库，能够被各个节点部署应用时使用

3. 在集群主节点部署该服务

   使用如下示例yaml文件配置服务

   ~~~yaml
   # ================= Deployment =================
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: os-backend-deploy
     namespace: k8s-learn
     labels:
       app: os-backend
   spec:
     replicas: 2
     selector:
       matchLabels:
         app: os-backend
     template:
       metadata:
         labels:
           app: os-backend
       spec:
         containers:
         - name: nginx
           image: os-backend-app:v1.0
           ports:
           - containerPort: 5001
   
   ---
   # ================= Service =================
   apiVersion: v1
   kind: Service
   metadata:
     name: os-backend-service
     namespace: k8s-learn
     labels:
       app: os-backend
   spec:
     type: NodePort
     selector:
       app: os-backend
     ports:
       - protocol: TCP
         port: 80
         targetPort: 5001
   ~~~

   需要注意的是，该前端界面暴露的容器端口是5001

   > 其实部署该服务，也可以使用如下链接的Operator，直接部署Deployment和对应的Service，不用这么麻烦的yaml
   >
   > https://github.com/WyYong7240/LSTMServerOperator

   部署完成后，如果能够成功执行如下命令，有对应的返回体，即为部署成功

   ~~~sh
   curl http://<HOSTIP>:<ServiceNodePort>/anomaly_detection
   ~~~
