* `httpserver-requests-total.go`

  ~~~go
  package main
  
  import (
  	"github.com/prometheus/client_golang/prometheus"
  	"github.com/prometheus/client_golang/prometheus/promhttp"
  	"net/http"
  	"time"
  )
  
  // 每当有人访问/路径时，记录一次请求，并统计请求耗时
  var (
  	// 请求计数器
  	requestCounter = prometheus.NewCounter(prometheus.CounterOpts{
  		Name: "myapp_requests_total",
  		Help: "Total number of requests received.",
  	})
  	// 请求延迟直方图,统计每次请求的耗时
  	requestDuration = prometheus.NewHistogram(prometheus.HistogramOpts{
  		Name: "myapp_request_duration_seconds",
  		Help: "Duration of requests in seconds",
  		// 线性分布的桶，从0.1秒开始，每个桶间隔0.1秒，共10个桶
  		Buckets: prometheus.LinearBuckets(0.1, 0.1, 10),
  	})
  )
  
  // 将自定义的指标注册到Prometheus的默认注册表中
  func init() {
  	prometheus.MustRegister(requestCounter)
  	prometheus.MustRegister(requestDuration)
  }
  
  func main() {
  	// 当访问根路径/时
  	http.HandleFunc("/", func(writer http.ResponseWriter, request *http.Request) {
  		start := time.Now()                                  // 记录当前时间
  		requestCounter.Inc()                                 // 调用INc方法，增加请求计数
  		requestDuration.Observe(time.Since(start).Seconds()) // 调用Observe记录请求耗时
  		writer.Write([]byte("Hello, Prometheus!"))           // 返回响应内容
  	})
  
  	// 挂载Prometheus的/metrics接口
  	// Prometheus Server通过该接口抓取应用指标
  	http.Handle("/metrics", promhttp.Handler())
  	// 监听本地8000端口，启动HTTP服务
  	http.ListenAndServe(":8000", nil)
  }
  ~~~

* `Dockerfile`

  ~~~dockerfile
  # 使用官方的 golang 镜像作为构建环境
  FROM golang:1.23.2 AS builder
  
  # 设置工作目录
  WORKDIR /app
  
  # 这是为了让构建镜像是，进行到RUN go mod download时，在没有VPN的情况下能够成功下载各个模块
  ENV GOPROXY=https://goproxy.cn,direct
  
  # 复制 go.mod 和 go.sum 文件（如果有）
  COPY go.mod go.sum ./
  
  # 下载所有依赖项。这很重要，因为这将不会使用缓存中的模块。
  RUN go mod download
  
  # 复制源代码
  COPY . .
  
  # 构建二进制文件
  RUN CGO_ENABLED=0 GOOS=linux go build -o myapp .
  
  # 使用最小的镜像作为最终镜像
  FROM alpine:latest
  
  # 设置工作目录
  WORKDIR /root/
  
  # 从构建阶段复制二进制文件到新的镜像中
  COPY --from=builder /app/myapp .
  
  # 上面的main.go代码中，指出的服务的端口是8000，所以这里需要暴露端口，如果需要暴露多个端口，采用EXPOSE 8000 443这样的方式
  EXPOSE 8000
  
  # 指定启动命令
  CMD ["./myapp"]
  ~~~

## 激活buildkitd

> 安装完成nerdctl-full后，buildkitd默认是没有运行的，需要先激活

* 查看是否安装了buildkitd

  ~~~bash
  which buildkitd
  ~~~

  如果有安装，应该有返回安装路径，例如`/usr/local/bin/buildkitd`

* 建立一个buildkitd的系统服务

  ~~~bash
  vim /etc/systemd/system/buildkit.service
  ~~~

  添加如下内容

  ~~~service
  [Unit]
  Description=BuildKit
  After=network.target containerd.service
  
  [Service]
  ExecStart=/usr/local/bin/buildkitd --config /etc/buildkit/buildkitd.toml
  Restart=always
  User=root
  
  [Install]
  WantedBy=default.target
  ~~~

  其中，`/usr/local/bin/buildkitd`是你的buildkitd安装路径，`/etc/buildkit/buildkitd.toml`是buildkitd构建镜像时，拉取基础镜像用的加速配置

- 具体参考文档：https://www.cnblogs.com/punchlinux/p/16575328.html

### BuildKit安装

1. buildkit包下载与安装
	``` bash
	wget https://github.com/moby/buildkit/releases/download/v0.10.3/buildkit-v0.10.4.linux-amd64.tar.gz
	tar -zxf buildkit-v0.10.4.linux-amd64.tar.gz
	mv /buildkit/bin/* /usr/bin/
	```

2. 设置BuildKit为系统服务
	``` bash
	cat /lib/systemd/system/buildkit.socket
	#######################################
	[Unit]
	Description=BuildKit
	Documentation=https://github.com/moby/buildkit
	
	[Socket]
	ListenStream=%t/buildkit/buildkitd.sock
	SocketMode=0660
	
	[Install]
	WantedBy=sockets.target
	
	
	cat /lib/systemd/system/buildkit.service
	#########################################
	[Unit]
	Description=BuildKit
	Requires=buildkit.socket
	After=buildkit.socket
	Documentation=https://github.com/moby/buildkit
	
	[Service]
	ExecStart=/usr/local/bin/buildkitd --oci-worker=false --containerd-worker=true
	
	[Install]
	WantedBy=multi-user.target
	```

3. 启动服务
	``` bash
	systemctl enable buildkit.service
	systemctl start buildkit.service
	```

## Dockerfile文件解析

## 以LSTM时间序列预测代理服务为例

* Dockerfile

  ~~~Dockerfile
  # 1️⃣ 基础镜像
  FROM python:3.9-slim
  
  # 2️⃣ 工作目录
  WORKDIR /app
  
  # 3️⃣ 拷贝项目文件
  COPY . /app
  
  # 4️⃣ 安装依赖
  RUN pip install --no-cache-dir -r requirements.txt
  
  # 5️⃣ 暴露端口
  EXPOSE 8080
  
  # 6️⃣ 启动命令
  CMD ["python", "predict_app_flask.py"]
  ~~~

  1. 第一行是该项目依赖的python镜像，一般来说建议使用-slim，让容器镜像能小一些，不然容器镜像非常大

  2. 第二行是在容器内创建一个工作目录，相当于容器的家目录，默认所有操作都会在/app下进行

  3. 第三行，则是将该Dockerfile同级目录下的所有文件都复制到容器的/app目录下

     例如，项目目录

     ~~~txt
     project/
     ├── predicate_app.py
     ├── lstm_multi_step.pth
     ├── scaler_multi_step.pkl
     ├── Dockerfile
     ~~~

     执行后的容器目录

     ~~~txt
     / (root)
     ├── app/
     │   ├── predicate_app.py       
     │   ├── lstm_multi_step.pth     
     │   ├── scaler_multi_step.pkl
     ~~~

     如果要将项目目录下的特定文件或文件夹复制到容器内

     ~~~Dockerfile
     COPY ./app /app
     ~~~

     这是将Dockefile所在目录的同级目录/app复制到容器内的/app文件夹下

     项目目录

     ~~~txt
     project/
     ├── app/
     │   ├── main.py
     │   ├── model.pth
     │   └── scaler.pkl
     ├── Dockerfile
     ~~~

     容器目录

     ~~~txt
     /app/
     ├── main.py
     ├── model.pth
     ├── scaler.pkl
     ~~~

  4. 第四行则是安装该python项目依赖的包

  5. 第五行，让容器向外暴露特定端口

  6. 第六行，容器启动命令，默认执行目录是WORKDIR创建的目录，上述中的就是/app

## 容器挂载解析

如果容器工作目录是`/app`

~~~txt
# 1️⃣ 基础镜像
FROM python:3.9-slim

# 2️⃣ 工作目录
WORKDIR /app

# 3️⃣ 拷贝项目文件
COPY . /app

# 4️⃣ 安装依赖
RUN pip install --no-cache-dir -r requirements.txt

# 5️⃣ 暴露端口
EXPOSE 8080

# 6️⃣ 启动命令
CMD ["python", "predict_app_flask.py"]
~~~

设定容器挂载的Deployment中的挂载yaml为

~~~yaml
volumeMounts:
  - name: model-volume
    mountPath: /app/model
~~~

`/app/model`是容器内部挂载路径

`home/user/model`是宿主机真实路径

则挂载完毕后，容器内部文件结构变为

~~~txt
/ (root)
├── app/
│   ├── predicate_app.py        ← Flask 服务主程序
│   ├── lstm_multi_step.pth     ← 如果没挂载，也会复制进去
│   ├── scaler_multi_step.pkl
│   ├── model/                  ← <== 这是挂载点
│       ├── lstm_multi_step.pth ← 实际来自 /home/user/models/
│       ├── scaler_multi_step.pkl
│       └── predictions.log     ← Flask 写入结果文件
~~~

其中/app/model下的文件都属宿主机真实路径下的文件，容器对/app/model下的文件操作都会真实反映到宿主机下的/home/user/model文件夹下
